## 1. 已确认需求

地面救援端使用 128x64 SSD1306 OLED，一次只显示一名受灾人员。屏幕下方两个物理按键用于切换人员；同时按下两个按键，在人员页和地面端本机环境页之间切换。

本机环境页显示：

- AHT20 温度；
- AHT20 湿度；
- 气体传感器 ADC 电压及风险状态。

人员页显示：

- 人员编号和当前序号；
- 到地面端的多跳链路估算路程；
- 血氧、心率；
- 电量、SOS；
- 链路状态和数据来源。

采用已经确认的第一种布局。现有五节点固定链路保持不变：

```text
受灾3 -> 受灾2 -> 受灾1 -> 天空搜救端 -> 地面救援端
COM15    COM9      COM12      COM11          COM14
```

## 2. 约束与非目标

1. 距离来自各跳 SLE RSSI 的经验估算并累计，是沿当前中继路径的近似路程，不是人员到地面端的直线测距，也不是 UWB/激光精确测距。屏幕统一加 `~` 前缀。
2. 气体传感器没有完成气种、零点和量程标定，因此只显示 ADC 毫伏值和经验风险状态，不显示 ppm、LEL 或任何法定浓度单位。
3. AHT20、MAX30102 和气体模块的数值用于演示与辅助判断，不作为医疗诊断或安全仪表结论。
4. 本次不修改无人机视频链路、不增加云平台、不改变五节点物理拓扑。
5. 传感器缺失、数据过期或报文错误时必须显示 `--`/`ERR`/`LOST`，不得用模拟值伪装为实测值。

## 3. 硬件映射

仅地面端启用本机 OLED、AHT20、气体 ADC 和两个按键：

| 功能 | WS63 接口 | 连接/参数 |
| --- | --- | --- |
| SSD1306 OLED | I2C1 | SDA GPIO15，SCL GPIO16，地址 0x3C，400 kHz |
| AHT20 | I2C1 | SDA GPIO15，SCL GPIO16，地址 0x38，400 kHz |
| 气体传感器模拟输出 | ADC5 | 物理 GPIO12；显示 ADC 毫伏值 |
| K1 | GPIO14 | 输入上拉，低电平按下 |
| K2 | GPIO13 | 输入上拉，低电平按下 |

OLED 与 AHT20 共用 I2C1，由一个总线互斥锁串行访问。地面端固件只初始化一次 I2C1。若驱动返回 `ERRCODE_I2C_ALREADY_INIT`，需显式将波特率设置为 400 kHz，避免沿用未知旧配置。

受灾端 MAX30102 仍使用各自板上的 I2C1/GPIO15/16。因为不同角色是不同固件、不同物理板，不与地面端总线冲突。

气体风险阈值沿用旧版已工作配置：

- `>= 1800 mV`：进入 `DANGER`；
- `<= 1500 mV`：恢复 `SAFE`；
- 1500~1800 mV：保持上一状态，形成迟滞，避免临界点抖动。

## 4. 软件结构

不继续把全部功能堆入已经较长的 `sle_relay.c`，新增三个边界清晰的模块。

### 4.1 `rescue_route`

所有五种角色共同编译，负责：

- 解析和重新编码 `JR` 报文包头；
- 保存原始 `src` 和业务 JSON；
- 每次向上游转发时递减 TTL、增加跳数并累计本跳距离；
- 将 RSSI 转为固定点分米，避免 OLED 和协议使用浮点格式；
- 对长度、整数范围、TTL 和字段完整性做边界检查。

该模块不依赖 SLE SDK，便于在电脑上直接编译执行单元测试。

### 4.2 `ground_monitor`

只在 `CONFIG_SAMPLE_SUPPORT_SLE_RELAY_ROOT` 下编译，负责：

- 解析 `VICTIM` 业务 JSON 的固定字段；
- 按 `VD-001`、`VD-002`、`VD-003` 更新三个固定缓存槽；
- 保存 `seq/spo2/hr/battery/sos/source/route_dm/hops/last_seen_ms`；
- 丢弃未知人员 ID、越界数值、旧序号和损坏报文；
- 为 UI 提供一次性快照，避免 OLED 读取到更新一半的数据；
- 依据最后接收时间生成 `OK/LOST/NO DATA` 状态。

报文解析、序号比较和缓存状态转换保持为不依赖 SDK 的纯 C 核心；OSAL 互斥锁和时钟读取放在薄包装层，保证核心逻辑也能在电脑上直接测试。

SLE 写回调是缓存的写入方，OLED 任务是读取方。二者用短时 OSAL 互斥锁保护，只在复制小结构时持锁，不在锁内执行 I2C 或串口输出。

### 4.3 `ground_ui`

只在地面端编译，负责：

- 初始化 I2C1、SSD1306、AHT20、ADC5、GPIO13/14；
- 独立采集本机温湿度和气体电压；
- 扫描并消抖两个按键；
- 从 `ground_monitor` 获取人员快照；
- 绘制人员页和环境页；
- 传感器失败时降级显示，但不影响 SLE 收包和转发。

初始化时先在 `sle_uart_server_init()` 之前完成 `ground_monitor` 缓存和互斥锁初始化，保证接收回调不会访问未初始化状态；SLE 服务启动后再启动实际 UI/环境任务。

两个任务分工：

- UI 任务每 10 ms 扫描按键，仅在内容变化或最长每 500 ms 刷新 OLED；
- 环境任务每 500 ms 读取气体 ADC，每 2 s 读取 AHT20。

AHT20 单次转换等待约 80 ms，放在环境任务中，因此不会漏掉短按按键。

## 5. 路由距离协议

### 5.1 包头格式

保留现有业务 JSON，只扩展 `JR` 包头：

```text
JR|src=3|dst=1|ttl=3|seq=17|hops=1|route_dm=24|route_ok=1|last_rssi=-61|{...VICTIM JSON...}
```

字段语义：

| 字段 | 含义 |
| --- | --- |
| `src` | 原始发送节点，转发时不改 |
| `dst` | 目标节点，地面端为 1 |
| `ttl` | 剩余可转发次数；每跳减 1，减到 0 后不再转发 |
| `seq` | 原始节点序号，与 `src` 共同去重 |
| `hops` | 已累计的上行链路段数量 |
| `route_dm` | 已累计估算路程，单位 0.1 m |
| `route_ok` | 所有经过链路是否都有有效 RSSI；0 时屏幕不显示部分距离 |
| `last_rssi` | 最近一跳的滤波 RSSI，仅用于诊断 |

旧报文缺少路由字段时仍可解析人员数据，但 `route_ok=0`，距离显示为 `~--.-m`。这样五块板分批升级时不会把不完整路程当成完整结果。

### 5.2 RSSI 采样与滤波

每个有上游连接的节点注册 `read_rssi_cb`，每 1 s 调用：

```text
sle_read_remote_device_rssi(g_upstream_conn_id)
```

只接受连接 ID 与当前上游连接一致、状态成功、RSSI 不等于无效值 127 且数值在 SDK 规定的 -127~20 dBm 范围内的回调。有效 RSSI 缓存最多使用 5 s；超时或断连后立即标记无效。滤波采用整数指数平均：

```text
filtered = (3 * previous + current) / 4
```

首次有效样本直接作为初值。断连后立即清除有效标志，重连取得新样本前不复用旧 RSSI。

### 5.3 RSSI 到距离

初始版本直接复用旧地面救援端已经运行过的整数分段换算，避免 `powf` 和额外数学库：

```text
rssi >= -45: 10 dm
-55..-46:   20 + (-45-rssi)*3 dm
-65..-56:   60 + (-55-rssi)*8 dm
-75..-66:  160 + (-65-rssi)*18 dm
-85..-76:  380 + (-75-rssi)*40 dm
rssi < -85: 900 dm
```

这仍是经验模型，后续可用现场 1 m、2 m、5 m、10 m 实测结果替换。总路程限制在协议整数范围内。只要任意一跳没有有效 RSSI，该包的 `route_ok` 变为 0，地面端不显示部分累计值。

## 6. 报文数据流

```text
受灾端生成 VICTIM JSON
        |
        v
加入本节点到上游的 RSSI 距离、hops+1、ttl-1
        |
        v
中继节点收到后解析包头
        |
        v
加入该中继到其上游的 RSSI 距离、hops+1、ttl-1
        |
        v
天空端执行相同操作
        |
        v
地面端校验 -> 更新三人缓存 -> OLED 显示
```

“增加本跳”的唯一入口放在 `relay_send_upstream()`：本地首发和所有转发包都经过同一逻辑，从而保证每条实际链路只累计一次。转发输入包的 TTL 必须大于 0；发送前将其减 1。减完为 0 的包仍允许完成当前发送并由地面端接收，但不得再被任何节点继续转发。

转发时先复制输入到有明确上限且以 NUL 结尾的工作缓冲区，再解析并编码到独立输出缓冲区。禁止直接把 SLE 回调提供的非 NUL 数据当普通 C 字符串使用。编码后既要小于协商 MTU 520，也要小于当前服务端 256 字节发送缓冲区；实际协议上限取 255 字节。超长、格式错误或输入 TTL 已为 0 时记录诊断日志并丢弃。

## 7. OLED 交互

### 7.1 人员页

128x64 屏幕使用 6x8 字体绘制五行，所有最长字符串均限制在 21 个 ASCII 字符以内：

```text
VD-001 1/3
PATH ~12.4m NEAR
SpO2 96 HR 78
BAT 82 SOS NO
LINK OK SRC MAX
```

显示规则：

- 没有完整距离：`~--.-m UNKNOWN`；
- 超过 6 s 未收到该人员新报文：`LINK LOST`；
- 从未收到：`NO DATA`；
- `source=MAX30102` 显示 `SRC MAX`；`source=SIM` 显示 `SRC SIM`，不掩盖模拟来源；
- 未检测到实测心率/血氧时显示 `SpO2 -- HR --`；
- 距离等级仅作速览并沿用旧版区间：`<=3 m VNEAR`、`3~12 m NEAR`、`12~35 m MID`、`>35 m FAR`。

### 7.2 本机环境页

```text
LOCAL ENV GROUND
TEMP 26.4C OK
HUM 58.0% OK
GAS 1240mV SAFE
SENSOR OK ENV
```

失败状态示例：

```text
LOCAL ENV GROUND
TEMP --.-C ERR
HUM --.-% ERR
GAS ----mV ERR
SENSOR ERR ENV
```

温湿度的 `OK` 仅表示本次读取成功，不表示医学或环境安全结论。气体状态使用带迟滞的 `SAFE/DANGER`。

### 7.3 按键规则

- 人员页短按 K1：上一人，VD-001/002/003 循环；
- 人员页短按 K2：下一人，VD-001/002/003 循环；
- K1+K2：人员页与本机环境页互相切换；
- 环境页单独按 K1/K2 不改变人员选择；
- 30 ms 稳定电平消抖；
- 手势在按键释放后触发；只要一次手势中曾同时按下两个键，就以双键为准，不误触发上一人/下一人；
- 长按不重复跳转，必须完全释放后才允许下一次手势。

## 8. 初始化与故障处理

1. 地面端先初始化人员缓存和互斥锁，再启动 SLE 服务，最后启动本机 UI/环境任务；UI 初始化失败不得阻止地面端收包。
2. OLED 地址 0x3C 探测失败时每 3 s 重试，串口记录 `OLED NOT_FOUND`，SLE 继续运行。
3. AHT20 校准最多重试 5 次；后续采样失败时保留错误状态，下一个 2 s 周期自动重试。示例驱动在持续 busy 时可能错误返回成功，因此包装层还必须检查温度 -40~85 C、湿度 0~100% 的合理范围。
4. ADC 初始化或读取失败时气体行显示 `ERR`；不能将 0 mV 当作有效安全值。
5. 业务报文解析失败只影响该报文，不清空其他人员的最后有效快照。
6. RSSI 请求失败或断连时清除本跳有效状态；不得沿用上一次连接的距离。
7. 所有关键路径增加可检索日志：`[RSSI]`、`[ROUTE_FWD]`、`[GROUND_CACHE]`、`[GROUND_UI]`、`[GROUND_ENV]`。
8. SSD1306 全屏刷新约发送 1 KB I2C 数据，驱动自身还有约 1 KB 的栈上发送缓冲，只在内容变化或 500 ms 保底周期刷新；独立 UI 任务栈使用 `0x3000`。

## 9. 构建隔离

`sle_relay/CMakeLists.txt` 按角色组织源文件：

- `rescue_route`：五个角色都编译；
- `ground_monitor`、`ground_ui`、AHT20、SSD1306、字体：只在 ROOT 定义存在时编译；
- MAX30102：继续用于受灾端代码路径；
- ADC 使用 WS63 LiteOS 已启用的 V154 驱动。

SSD1306 使用工程现有 `src/application/samples/peripheral/helloworld_oled` 驱动；AHT20 使用同一 SDK 树内 HiHope environment demo 驱动。对外部示例驱动的返回值缺陷用本项目包装层补强，不把错误结果当成功。

正式构建只启用 `CONFIG_SAMPLE_SUPPORT_SLE_RELAY`，不得同时启用会编译另一套同名 SSD1306 源文件的 `CONFIG_SAMPLE_SUPPORT_SLE_UART_CLIENT/SERVER`。CMake 只给 ROOT 角色一个 OLED 驱动所有者，避免重复符号。

构建产物写入新的时间戳 staging 目录，不覆盖当前可回滚的 `delivery/firmware`：

```text
D:\table\jiuyuan\delivery\staging\ground-ui-distance-env-YYYYMMDD-HHmmss
```

因为每个中继都必须累计本跳距离，本功能需要重新构建并烧录五块板，不能只烧地面端。

### 10.3 烧录与串口验收

在端口重新出现且无人占用后，按以下映射烧录：

| 角色 | 串口 |
| --- | --- |
| 地面 | COM14 |
| 天空 | COM11 |
| 受灾1 | COM12 |
| 受灾2 | COM9 |
| 受灾3 | COM15 |

建议按受灾3、受灾2、受灾1、天空、地面的顺序烧录，地面最后启动完整新协议。每块板烧录前校验 staging 包 SHA256，烧录后按一次 RESET。

串口验收必须看到：

- 五块板角色和 ID 正确；
- 每个上游节点持续获得有效 RSSI；
- 地面端收到 VD-001/002/003，且 hops 分别随链路深度增加；
- 有效包带 `route_ok=1` 和累计 `route_dm`；
- 地面端 OLED、AHT20、ADC、按键初始化日志无致命错误；
- 断开任一中继后，相关人员在 6 s 后显示 `LINK LOST`；恢复后自动回到 `LINK OK`。

### 10.4 实物界面验收

1. 默认人员页一次只显示一人。
2. K1/K2 单次短按各跳一人，长按不连跳。
3. 两键同时按只切换页面，不顺带切人。
4. 环境页能看到温度、湿度、气体 mV 和状态。
5. 拔掉 AHT20 或气体信号后显示错误，而不是假值；SLE 人员数据仍继续刷新。
6. 三个人员页面均能显示各自数据、链路状态和近似路程。
