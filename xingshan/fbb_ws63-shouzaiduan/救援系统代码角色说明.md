# 救援系统代码角色说明

更新时间：2026-07-14

## 1. 结论

当前实际用于五节点救援网络的源码目录是：

```text
D:\table\jiuyuan\xingshan\fbb_ws63-shouzaiduan\fbb_ws63-master\src
```

虽然目录名是 `shouzaiduan`，但该目录现在已经不是“只包含受灾端”的工程，而是一个通过编译宏生成五种固件的共用工程：

- 地面救援端
- 天空搜救端
- 受灾端 1
- 受灾端 2
- 受灾端 3

不能再根据顶层目录名判断固件角色。最终角色由构建命令中的 `CONFIG_SAMPLE_SUPPORT_SLE_RELAY_*` 宏决定。

## 2. 两个工程目录的区别

### 当前五节点共用工程

```text
D:\table\jiuyuan\xingshan\fbb_ws63-shouzaiduan\fbb_ws63-master\src
```

该工程包含当前五节点系统需要的完整功能：

- ROOT、SKY、VICTIM 三类角色选择
- 三个受灾端编号
- 地面端 OLED、小系统按键、温湿度和气体传感器
- 受灾端 MAX30102
- SLE 多跳转发
- RSSI 路径距离协议
- 地面端、路由协议和 MAX30102 测试

`delivery\build_rescue_network.ps1` 当前明确从这个目录复制源码并构建五份固件。

### 旧的救援端工程

```text
D:\table\jiuyuan\xingshan\fbb_ws63-jiuyuanduan\fbb_ws63-master\src
```

该目录中的 `sle_relay` 仍是较早的简化中继版本。与当前共用工程相比，它没有以下文件：

- `ground_ui.c/.h`
- `ground_model.c/.h`
- `aht20.c/.h`
- `rescue_route.c/.h`

它的 Kconfig 也没有 `VICTIM` 角色和受灾端编号配置。因此，当前不能直接把这个旧目录当成完整地面端工程进行五节点构建。

### 临时构建目录

```text
D:\jr\n
```

这是为避免 Windows 命令行过长而使用的短路径构建副本，不是源码主目录。这里的内容可能被构建脚本删除并重新同步，不应作为长期代码来源。

### 固件交付目录

```text
D:\table\jiuyuan\delivery\firmware
D:\table\jiuyuan\delivery\staging
```

这里存放编译产物、临时烧录包和 SHA256 清单，不是源代码。

## 3. 五个设备的角色映射

| 设备 | 串口 | 编译角色 | 节点 ID | 广播名 | 主动连接目标 |
| --- | --- | --- | ---: | --- | --- |
| 地面救援端 | COM14 | `ROOT` | 1 | `jr_ground` | 无 |
| 天空搜救端 | COM11 | `NODE` | 2 | `jr_sky` | `jr_ground` |
| 受灾端 1 | COM12 | `VICTIM index=1` | 3 | `jr_v1` | `jr_sky` |
| 受灾端 2 | COM9 | `VICTIM index=2` | 4 | `jr_v2` | `jr_v1` |
| 受灾端 3 | COM15 | `VICTIM index=3` | 5 | `jr_v3` | `jr_v2` |

固定数据链路为：

```text
受灾端3(COM15)
    -> 受灾端2(COM9)
    -> 受灾端1(COM12)
    -> 天空搜救端(COM11)
    -> 地面救援端(COM14)
```

## 4. 各角色的编译宏

### 地面救援端

```text
CONFIG_SAMPLE_SUPPORT_SLE_RELAY_ROOT=y
```

### 天空搜救端

```text
CONFIG_SAMPLE_SUPPORT_SLE_RELAY_NODE=y
```

### 受灾端

```text
CONFIG_SAMPLE_SUPPORT_SLE_RELAY_VICTIM=y
CONFIG_SLE_RELAY_VICTIM_INDEX=1/2/3
```

三个角色共用同一份 `sle_relay.c`，通过 `#if defined(...)` 选择实际编译的代码分支。

## 5. 地面救援端代码

地面端专用文件位于：

```text
application\samples\products\sle_relay\ground_ui.c
application\samples\products\sle_relay\ground_ui.h
application\samples\products\sle_relay\ground_model.c
application\samples\products\sle_relay\ground_model.h
application\samples\products\sle_relay\aht20.c
application\samples\products\sle_relay\aht20.h
```

职责如下：

| 文件 | 职责 |
| --- | --- |
| `ground_ui.c/.h` | OLED 页面、S1/S2 按键、人员页、环境页、气体 ADC、AHT20 |
| `ground_model.c/.h` | 三个人员的数据模型、报文解析、页面状态机、按键消抖 |
| `aht20.c/.h` | 地面端温湿度传感器驱动 |

地面端还会编译公共 OLED 驱动：

```text
application\samples\peripheral\helloworld_oled\ssd1306.c
application\samples\peripheral\helloworld_oled\ssd1306_fonts.c
```

这些地面专用文件只在 `ROOT` 构建时由 `sle_relay/CMakeLists.txt` 加入，不会进入 SKY 或 VICTIM 固件。

## 6. 天空搜救端代码

天空端目前没有单独的 `sky.c`。天空端逻辑主要位于共享文件中的 `NODE` 条件分支：

```text
application\samples\products\sle_relay\sle_relay.c
application\samples\products\sle_relay\sle_uart_server\sle_uart_server_adv.c
```

天空端职责：

- 以 `jr_sky` 名称提供下游 SLE 服务
- 主动扫描并连接地面端 `jr_ground`
- 接收受灾端 1 的数据
- 给数据增加天空到地面的 RSSI 距离信息
- 将数据转发给地面救援端

修改天空端行为时，必须确认代码位于 `CONFIG_SAMPLE_SUPPORT_SLE_RELAY_NODE` 分支，或者确认修改确实应该影响所有角色。

## 7. 受灾端代码

受灾端的角色逻辑主要位于：

```text
application\samples\products\sle_relay\sle_relay.c
application\samples\products\sle_relay\sle_uart_server\sle_uart_server_adv.c
```

MAX30102 驱动位于：

```text
application\samples\products\sle_uart\max30102.c
application\samples\products\sle_uart\max30102.h
```

受灾端职责：

- 根据 `CONFIG_SLE_RELAY_VICTIM_INDEX` 生成 `VD-001/002/003`
- 读取 MAX30102 心率和血氧
- 传感器不可用时发送标记为 `SIM` 的演示数据
- 生成受灾人员状态报文
- 连接固定上游节点
- 受灾端 1、2 还负责转发下游受灾端数据

三个受灾端没有三套独立源码，而是同一代码通过 index 生成三个固件。

## 8. 三类角色共用的代码

```text
application\samples\products\sle_relay\sle_relay.c
application\samples\products\sle_relay\rescue_route.c
application\samples\products\sle_relay\rescue_route.h
application\samples\products\sle_relay\sle_uart_server\sle_uart_server.c
application\samples\products\sle_relay\sle_uart_server\sle_uart_server.h
application\samples\products\sle_relay\sle_uart_server\sle_uart_server_adv.c
application\samples\products\sle_relay\sle_uart_server\sle_uart_server_adv.h
```

| 文件 | 影响范围 |
| --- | --- |
| `sle_relay.c` | 角色选择、连接、收发、转发、RSSI 采集，可能影响全部五个设备 |
| `rescue_route.c/.h` | 多跳路径、RSSI 距离累计和报文格式，影响天空端、受灾端和地面解析 |
| `sle_uart_server/*` | SLE 服务、广播名称和连接接口，影响所有提供下游服务的角色 |

修改这些共享文件后，通常需要重新构建并烧录整条链路，不能只更新 COM14。

## 10. 后续修改边界

- 只改地面屏幕、按键或本地环境传感器：修改 `ground_ui.*` 或 `ground_model.*`，只构建 ROOT。
- 只改受灾端 MAX30102：修改 `max30102.*` 或 `sle_relay.c` 的 VICTIM 分支，构建三个 VICTIM 固件。
- 只改天空转发策略：修改 `sle_relay.c` 的 NODE 分支，构建 SKY。
- 修改报文、路由、RSSI 距离或公共 SLE 收发：属于共享协议变更，应重新构建并烧录五个角色。
- 判断固件角色时，先看构建宏和固件文件名，不要根据 `shouzaiduan` 或 `jiuyuanduan` 目录名直接判断。

## 11. 当前需要注意的版本一致性

地面端可以兼容接收旧版人员报文，因此即使天空端或受灾端固件较旧，人员信息仍可能显示为 `LINK OK`。但旧版报文没有以下字段：

```text
hops
route_dm
route_ok
last_rssi
```

这种情况下距离会显示 `PATH ~--.-m UNKNOWN`。要显示路径距离，天空端和三个受灾端必须与地面端使用同一版共享路由协议。
